# Learning to Learn Is the Meta-Skill (Make It First-Class)

**Thesis (captain, verbatim intent):** learning to learn from our mistakes is
a meta-skill, and the program should treat it as a first-class capability —
not an emergent nicety of good process.

## The three loops, observed in one day (2026-07-18/19)

1. **Fix the mistake** (single-loop): a validator FAILs a PR; the seat
   iterates; re-validation passes. Routine by design.
2. **Fix the system that produced it** (double-loop): casualties → `candidate:`
   lines → `dispatch-flight-rules` policy, merged same-day; the debrief
   legislates so the class of mistake dies, not the instance.
3. **Fix how the fixing works** (triple-loop — the meta-skill): the feeding
   loop itself amended into a two-speed structure; the review posture upgraded
   after the corpus incident, where the seat proposed maintaining a workaround
   (auto-mirror machinery) and the captain saw the second source of truth
   shouldn't exist at all. Bridge-thinking stabilizes; architecture-thinking
   asks whether the stabilized thing should survive. The program must keep
   both and know which one it is doing.

## The practice this seed proposes

Every debrief answers three questions, not one: *what did we learn* (loop 1),
*what law prevents the class* (loop 2), and *did the learning machinery itself
perform — what would have caught this sooner, cheaper, or without the captain?*
(loop 3). A debrief that only answers the first is a log, not learning.
